# 关于「内嵌 CPU-Z / MemTest86」的说明

## 结论：不能内嵌，但可以用自研实现达到同样效果

### CPU-Z

- CPU-Z 是 **CPUID 公司的专有软件**（免费使用，但版权保留）。
  它的最终用户许可禁止再分发、禁止随第三方程序打包。
  把它内嵌进 JunkCleaner 再分发属于侵权行为，我不能这么做。
- 而且它的核心信息（CPU 型号、核心/线程、缓存、指令集、主板、内存 SPD）
  本来就来自公开接口（CPUID 指令、SMBIOS、SPD）。

**替代方案**：我们自己实现一个「CPU 信息 + 跑分 + 压力测试」模块，
数据源用同样的公开接口，效果等价，且没有授权问题。

### MemTest86 / MemTest86+

- **MemTest86**（PassMark）是专有软件，同样不可内嵌。
- **MemTest86+** 是 GPL 开源，但它是一个**独立启动镜像**
  （写到 U 盘后从 BIOS 启动），不是 Windows 程序，
  没法「解包逻辑塞进 Windows 应用」。
- 更关键的是原理限制：**Windows 运行时无法测试它自己正在使用的内存**。
  MemTest86 之所以要脱离操作系统启动，就是为了独占全部物理内存。

**替代方案**：实现一个 Windows 级别的内存测试模块
（分配大块内存、写入测试图案、读回校验、报告错误），
可以查出多数不稳定问题，但**测不到 Windows 自己占用的那部分内存**。
要全面测内存仍需从 U 盘启动 MemTest86+（GPL，可自由下载）。

### 内存频率 / 时序 / 电压

DDR4 的频率、时序、电压由 **BIOS 在开机自检阶段**通过 SPD 与内存控制器协商设定，
运行时**没有任何用户态接口可以改**：

- Intel 平台没有开放运行时改 DRAM timing 的接口（XTU 也不行）
- 主板厂商的 Windows 工具（如华硕 AI Suite）也只是**改 BIOS 设置后要求重启**
- 内存条上的 SPD 是 EEPROM，改写它属于刷写操作，风险极高且不生效于当次开机

**替代方案**：我们**读取并展示**当前 SPD/时序/频率（含 XMP 状态），
并给出建议值；实际修改请在 BIOS 里完成。

## 我们的实现

| 需求 | 原方案 | 我们的实现 |
|------|--------|-----------|
| CPU 信息 | CPU-Z | 读 CPUID / SMBIOS / 注册表，自研 |
| CPU 跑分 | CPU-Z Bench | 自研单核/多核基准 |
| CPU 压力测试 | CPU-Z Stress | 自研全核负载 + 温度/降频监控 |
| 内存测试 | MemTest86 | 自研 Windows 级图案测试 |
| 内存时序显示 | CPU-Z SPD 页 | 读 SMBIOS Type 17 |
| 内存时序修改 | — | 只能进 BIOS（如实告知） |
